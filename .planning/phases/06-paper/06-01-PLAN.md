# Phase 6 논문 작성·제출 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Phase 1~5의 검증된 산출물을 서론/방법/결과/논의 구성의 완성 논문(통합 참고문헌·~10줄 초록·표지 포함)으로 조립하고, 원시 데이터·결함 주입 스크립트·실행 절차를 단일 ZIP 재현 패키지로 묶고, 3줄 AI-대-본인 판단 공개를 붙여 한 세트로 제출 가능한 상태로 만든다. 미완성 표시·플레이스홀더·근거 없는 주장·잘못된 인용이 없어야 한다.

**Architecture:** 논문은 이미 존재하는 검증된 문서에서 조립한다 — 배경/선행연구·CVE는 `docs/research/phase-1-*`·`cve-2026-2673.md`·`background-cves.md`, 방법은 `phase-2-environment.md`·`phase-3-experiment-design.md`·`phase-4-execution.md`·`tools/faultinject/`, 결과·논의는 `phase-5-analysis.md`·`manifest.csv`. 새 실험·새 주장은 만들지 않는다. 참고문헌은 `phase-1-source-ledger.md`의 `검증됨` 항목만 쓰며 귀속을 정확히 한다. 재현 패키지는 스크립트로 ZIP을 만들고, 다른 위치에 풀어 파일 누락이 없는지 검증한다.

**Tech Stack:** Markdown(논문 `docs/PAPER.md`, 프로젝트·PROPOSAL과 동일한 한국어), Python 표준 라이브러리(ZIP 빌더·검증), 기존 원시 데이터·도구. PDF 변환은 선택(요청 시 pdf 스킬로 별도 생성).

**Spec:** `.planning/REQUIREMENTS.md`의 `REQ-reproduction-package`, `.planning/ROADMAP.md` Phase 6 성공 기준, `docs/PROPOSAL.md`, `docs/research/phase-1-source-ledger.md`(참고문헌 원장), Phase 2~5 문서.

## Global Constraints

- **원시 데이터 밖 주장 금지**: 결과·논의의 모든 수치·판정은 `raw/phase-4/`·`manifest.csv`·`phase-5-analysis.md`의 실제 값을 인용한다. Phase 5가 고정한 "부분적 지지"(group-list=패턴, binding=세 구현 방어) 판정을 그대로 따르고 확대하지 않는다.
- **CVE와의 구분 유지**: 본 실험의 group-list 다운그레이드는 관측 가능(`downgrade_visible=true`)하며, CVE-2026-2673의 "조용한" 다운그레이드는 재현하지 못했다는 한계를 논문 본문·논의에 반드시 명시한다.
- **인용 정확성**: 참고문헌은 `phase-1-source-ledger.md`의 `검증됨` 항목만 사용한다. 귀속을 정확히 한다 — 다운그레이드 저항성 정의는 **Bhargavan et al., "Downgrade Resilience in Key-Exchange Protocols", IEEE S&P 2016**; transcript-bound combiner는 **Gupta & Rana, "Transcript-Bound Combiners…", arXiv:2609.21273 (2026)**. 두 문헌을 혼동·병합하지 않는다(기존 문서의 혼동은 Task 1에서 교정).
- **재현성**: ZIP은 원시 데이터 + `tools/faultinject/` + 실행 절차(README)를 포함하고, 저장소 밖 임의 위치에 풀어도 참조 파일 누락이 없어야 한다. 절대 경로·기계 고유 경로에 의존하지 않는다.
- **완결성**: 최종 산출물에 `TBD`·`TODO`·플레이스홀더·빈 절이 없어야 한다.
- **정직성 공개**: AI가 수행한 부분과 사람이 수행·결정한 부분을 3줄로 정직하게 공개한다(과장·축소 없이).

## Review Focus

- 논문의 모든 결과 문장이 실제 데이터 값을 인용하는가, Phase 5 판정을 넘어서지 않는가.
- CVE의 "조용한 다운그레이드"를 재현했다고 오독될 문장이 없는가(관측 가능 vs 조용함 구분 유지).
- 참고문헌 귀속이 정확한가 — Bhargavan(2016) ≠ Transcript-Bound Combiners(Gupta & Rana 2026). 원장의 URL과 일치하는가.
- ZIP이 임의 위치에서 풀려 실행 절차대로 재현 가능한가, 누락 파일이 없는가.
- AI-대-본인 공개가 정직한가(이 프로젝트는 AI 주도 구현·사람 결정/검증 게이트였음을 반영).
- 표지·초록·서론/방법/결과/논의·참고문헌이 모두 채워졌고 플레이스홀더가 없는가.
