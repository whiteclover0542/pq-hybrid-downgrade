# Phase 2 실험 환경 구축 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 독립적인 3개 하이브리드-KEM 구현(OpenSSL+oqs-provider, BoringSSL, OpenSSH)을 버전 고정해 로컬에 빌드하고, 조작 없는 정상 하이브리드 핸드셰이크의 기준선(baseline)을 원자료로 확보한다.

**Architecture:** 하나의 빌드 환경을 먼저 확정하고, 구현체별로 (빌드 → 하이브리드 핸드셰이크 성공 확인 → baseline 로그·패킷 캡처 저장)을 독립적으로 수행한다. 세 구현체의 버전·커밋·빌드 옵션과 감사 경로를 단일 환경 대장(environment ledger)에 기록해 Phase 3~4가 그대로 참조한다.

**Tech Stack:** OpenSSL 3.5/3.6 + oqs-provider(liboqs), BoringSSL(CMake+Ninja+Go), OpenSSH(하이브리드 KEM 지원 버전), Wireshark/tshark, SSLKEYLOGFILE. 빌드 환경은 Task 1에서 확정(WSL2 Linux 우선 검토, 대안 MSYS2/네이티브).

**Spec:** `.planning/REQUIREMENTS.md`의 `REQ-testbed-three-implementations`, `.planning/ROADMAP.md`의 Phase 2 성공 기준, `docs/research/phase-1-synthesis.md`의 Phase 2 인계 조건.

## Global Constraints

- **버전 고정**: 세 구현체 모두 정확한 버전·커밋 해시·빌드 옵션을 기록한다. 결함이 특정 버전에만 존재할 수 있어 재현에 필수다.
- **취약 버전 선택**: OpenSSL은 CVE-2026-2673 영향 범위(3.5.0~3.5.5 또는 3.6.0~3.6.1) 중 **수정 전 취약 커밋**을 고른다 — Phase 4 다운그레이드 재현의 전제.
- **baseline은 조작 없이**: 이 단계에서는 결함 주입을 하지 않는다. 정상 하이브리드 핸드셰이크가 성립하는 상태만 기록한다.
- **원자료 보존**: 모든 baseline 로그·패킷 캡처를 파일로 남기고 사전 삭제하지 않는다. 파일명/메타에 구현체·버전·날짜를 인코딩한다.
- **환경 명시**: 실행 OS·커널(WSL 배포판 포함)·툴체인 버전을 대장에 적어 제3자가 같은 환경을 재현할 수 있게 한다.

## Review Focus

- 하이브리드 그룹이 실제로 협상됐는지 vs 고전 그룹으로 조용히 성립했는지 — baseline이 진짜 하이브리드인지 로그의 key_share 그룹으로 확인한다.
- oqs-provider가 OpenSSL에 로드됐는지 — provider 미로딩 시 하이브리드 그룹이 없는데도 핸드셰이크가 성공해 baseline을 오판할 수 있다.
- BoringSSL과 OpenSSL의 하이브리드 그룹 명칭·코드포인트 차이 — 같은 알고리즘이라도 그룹 ID가 달라 혼동 가능.
- 빌드했지만 시스템 기본 바이너리를 실행하는 경우 — `which`/절대경로로 방금 빌드한 바이너리를 쓰는지 확인한다.
- 버전을 "최신"으로만 적고 커밋을 안 남기는 경우 — 재현 불가. 커밋 해시를 반드시 기록한다.

### Task 1: 빌드 환경 확정과 버전 고정

**Files:**
- Create: `docs/research/phase-2-environment.md` (환경·버전 대장)

**Interfaces:**
- Consumes: `docs/research/phase-1-synthesis.md`(인계 조건), `docs/research/cve-2026-2673.md`(영향 버전)
- Produces: 이후 모든 Task가 참조할 빌드 OS/툴체인, 3개 구현체의 대상 버전·커밋

- [ ] **Step 1: 빌드 환경을 결정한다**

  Windows에서 세 구현체를 빌드할 방법을 정한다: WSL2(Linux 배포판) 우선 검토, 대안으로 MSYS2/네이티브. 선택한 환경의 OS·커널·배포판 버전을 `phase-2-environment.md`에 기록한다. 이유도 한 줄 남긴다(예: oqs-provider·OpenSSH 하이브리드 KEM은 Linux 빌드가 문서화가 풍부함).

- [ ] **Step 2: 대상 버전·커밋을 고정한다**

  세 구현체의 정확한 대상을 표로 고정한다:
  - OpenSSL: CVE-2026-2673 영향 범위(3.5.0~3.5.5 또는 3.6.0~3.6.1) 중 **수정 전 취약 커밋** 1개 + liboqs/oqs-provider 버전
  - BoringSSL: 대상 커밋 해시
  - OpenSSH: 하이브리드 KEM(sntrup761x25519-sha512) 지원 버전·커밋
  각 대상 그룹(X25519MLKEM768 / X25519Kyber768 / sntrup761x25519-sha512)도 함께 적는다.

- [ ] **Step 3: 툴체인을 준비한다**

  선택 환경에 필요한 빌드 도구를 설치·확인한다(컴파일러, CMake, Ninja, Go, Perl 등). 설치한 도구의 버전을 대장에 기록한다.

  검증: 각 도구 `--version` 출력이 대장에 기록되어 있다.

### Task 2: OpenSSL + oqs-provider 빌드와 baseline

**Files:**
- Modify: `docs/research/phase-2-environment.md`
- Create: `docs/research/baselines/openssl-baseline.md`

**Interfaces:**
- Consumes: Task 1의 대상 버전·커밋
- Produces: oqs-provider 로드된 OpenSSL 빌드, X25519MLKEM768 정상 핸드셰이크 baseline

- [ ] **Step 1: liboqs와 oqs-provider를 빌드하고 OpenSSL에 연결한다**

  고정한 OpenSSL 커밋을 빌드하고 oqs-provider를 로드한다. `openssl list -providers`로 oqs-provider가 로드됐는지 확인한다.

- [ ] **Step 2: 하이브리드 핸드셰이크를 성립시킨다**

  방금 빌드한 바이너리로 `s_server`/`s_client`를 X25519MLKEM768 그룹으로 연결한다. 절대경로로 빌드 바이너리를 실행했는지 확인한다.

- [ ] **Step 3: baseline을 기록한다**

  `-state`·`SSLKEYLOGFILE`·패킷 캡처로 협상된 그룹이 X25519MLKEM768임을 확인하고 `openssl-baseline.md`와 원자료 파일로 저장한다.

  검증: baseline 로그에 협상 그룹 = X25519MLKEM768이 나타난다.

### Task 3: BoringSSL 빌드와 baseline

**Files:**
- Modify: `docs/research/phase-2-environment.md`
- Create: `docs/research/baselines/boringssl-baseline.md`

**Interfaces:**
- Consumes: Task 1의 대상 커밋
- Produces: BoringSSL 빌드, X25519Kyber768 정상 핸드셰이크 baseline

- [ ] **Step 1: BoringSSL을 빌드한다**

  고정한 커밋을 CMake+Ninja(+Go)로 빌드하고 `bssl` 도구를 확보한다.

- [ ] **Step 2: 하이브리드 핸드셰이크를 성립시킨다**

  `bssl server`/`bssl client`를 X25519Kyber768로 연결한다. BoringSSL의 그룹 명칭·코드포인트가 OpenSSL과 다를 수 있으니 실제 협상 그룹을 확인한다.

- [ ] **Step 3: baseline을 기록한다**

  협상 그룹과 핸드셰이크 성공을 로그·캡처로 `boringssl-baseline.md`에 저장한다.

  검증: baseline 로그에 하이브리드 그룹(X25519Kyber768) 협상이 나타난다.

### Task 4: OpenSSH 하이브리드 KEM 빌드와 baseline

**Files:**
- Modify: `docs/research/phase-2-environment.md`
- Create: `docs/research/baselines/openssh-baseline.md`

**Interfaces:**
- Consumes: Task 1의 대상 버전·커밋
- Produces: OpenSSH 빌드, sntrup761x25519-sha512 정상 핸드셰이크 baseline

- [ ] **Step 1: OpenSSH를 빌드한다**

  하이브리드 KEM을 지원하는 고정 버전을 빌드하고 `sshd`/`ssh` 바이너리를 확보한다.

- [ ] **Step 2: 하이브리드 KEX를 성립시킨다**

  `sshd -o KexAlgorithms=sntrup761x25519-sha512@openssh.com`로 로컬 서버를 띄우고 `ssh -vvv`로 연결해 해당 KEX가 협상됐는지 확인한다.

- [ ] **Step 3: baseline을 기록한다**

  `-vvv` 로그와 패킷 캡처로 협상 KEX를 확인하고 `openssh-baseline.md`에 저장한다.

  검증: `-vvv` 로그에 sntrup761x25519-sha512 KEX 협상이 나타난다.
