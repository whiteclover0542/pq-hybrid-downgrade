# Phase 3 실험 도구 개발 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Phase 2의 세 baseline을 기준선으로 삼아, 통제된 loopback 환경에서 하이브리드 협상 필드에 2유형의 결함을 주입하는 재현 도구와, 매 실행의 관측 지표 3종을 구조화 원시 데이터로 자동 기록하는 하네스를 만든다. 그리고 "조작이 실제로 적용됐는지"를 확인해 도구 실패를 무결함 결과로 오독하지 않게 하는 검증 스크립트를 붙인다.

**Architecture:** 개입 지점을 결함별로 나눈다. 결함1(그룹 목록 조작)은 각 구현체 클라이언트의 **구성/CLI 레벨**에서 지원 그룹 목록을 바꿔 고전 폴백을 유도한다. 결함2(결합자 바인딩 위반)는 클라이언트-서버 사이의 **TLS 레코드 계층 MITM 프록시**에서 key_share의 한 성분만 위조해 transcript-binding 검증 여부를 시험한다. 두 경로 모두 동일한 **관측 하네스**(`harness.py`)를 호출해 지표 3종을 같은 JSON 스키마로 기록하고, 동일한 **적용 검증기**(`verify_applied.py`)로 조작이 네트워크에 실제 반영됐는지 확인한다. 도구는 Phase 2가 고정한 절대 경로 바이너리·환경 변수만 사용한다.

**Tech Stack:** Python 3(표준 라이브러리 + `scapy`는 pcap 파싱에만 선택 사용), `tshark`(패킷 재검증), Phase 2에서 빌드한 OpenSSL 3.5.5+oqs-provider / BoringSSL / OpenSSH 바이너리, WSL2 Ubuntu(Phase 2 환경 대장 그대로).

**Spec:** `.planning/REQUIREMENTS.md`의 `REQ-fault-injector`·`REQ-observation-metrics`, `.planning/ROADMAP.md` Phase 3 성공 기준, `docs/PROPOSAL.md` 4.1~4.4, `docs/research/phase-2-environment.md`의 Phase 3 인계 조건.

## Global Constraints

- **연구 성격**: 통제된 로컬 loopback 실험이다. 실네트워크·타 호스트·미승인 대상에 도구를 쓰지 않는다. 목적은 이미 공개된 CVE-2026-2673 계열의 다운그레이드가 감사 도구에 드러나는지 재현·측정하는 것이다.
- **Phase 2 환경 고정**: 세 구현체는 `docs/research/phase-2-environment.md`가 기록한 절대 경로 바이너리·커밋·`LD_LIBRARY_PATH`·`OPENSSL_MODULES`·KEX 강제 옵션만 사용한다. 시스템 기본 바이너리가 섞이면 비교가 무효다. 매 실행 전 provider/그룹 로딩을 재확인한다.
- **기준 협상값(baseline)**: 정상값은 OpenSSL `X25519MLKEM768`, BoringSSL `X25519Kyber768Draft00`(code point `0x6399`), OpenSSH `sntrup761x25519-sha512@openssh.com`. 무엇이 이 값에서 벗어나면 다운그레이드인지 판단 기준이 된다.
- **원시 데이터 보존**: 모든 실행 로그·pcap·JSON 레코드를 파일로 남기고 사전 삭제하지 않는다. 파일명/메타에 구현체·결함유형·반복번호·실행조건을 인코딩한다(Phase 4가 이 규칙을 그대로 쓴다).
- **조용한 실패 구분**: 조작이 네트워크에 실제 반영되지 않은 실행(도구 버그)과, 조작이 반영됐는데 구현체가 그대로 성립시킨 실행(진짜 무결함)을 반드시 구분한다. 전자는 결과 데이터에서 `manipulation_verified=false`로 격리한다.
- **결함2 실패는 데이터다**: 레코드 조작 후 핸드셰이크가 거부/실패해도 그것이 곧 관측 지표(핸드셰이크 성공/실패)다. 단, 그 실패가 프록시의 파싱 버그 때문인지 구현체의 바인딩 검증 때문인지 검증기로 갈라야 한다.

## Review Focus

- 하네스가 협상 그룹을 client log에서 정확히 뽑는가 — 정규식이 세 구현체의 실제 출력 문자열과 일치하는지 Phase 2 baseline 로그로 먼저 검증한다.
- 결함1에서 "그룹 목록을 조작했다"와 "서버가 고전으로 폴백했다"를 혼동하지 않는가 — 전자는 ClientHello 입력, 후자는 협상 결과다. 둘 다 따로 기록한다.
- 결함2에서 프록시가 레코드 경계를 잘못 잘라 핸드셰이크를 깨뜨린 것을 "바인딩 위반이 걸러졌다"로 오판하지 않는가 — 검증기가 조작 바이트가 서버에 도달했는지 확인해야 한다.
- 도구가 Phase 2 절대 경로 바이너리가 아니라 시스템 기본을 실행하지 않는가 — 하네스가 실행 전 바이너리 경로와 provider 로딩을 로그로 남긴다.
- JSON 스키마가 Phase 4의 반복 실행·집계에 그대로 쓰일 수 있는가 — 필드가 구현체·결함유형·반복·조건·지표3종을 모두 담는지 확인한다.

```python
# tools/faultinject/record.py
from __future__ import annotations
import json
from dataclasses import dataclass, asdict, field
from pathlib import Path

HYBRID_GROUPS = {
    "X25519MLKEM768", "X25519Kyber768Draft00",
    "sntrup761x25519-sha512@openssh.com",
}

def run_id(impl: str, fault: str, rep: int, condition: str) -> str:
    return f"{impl}_{fault}_r{rep:02d}_{condition}"

@dataclass
class Metrics:
    negotiated_group: str | None
    is_hybrid: bool
    downgrade_visible: bool
    handshake_result: str  # "success" | "failure"
    detail: str = ""

@dataclass
class RunRecord:
    run_id: str
    implementation: str
    fault_type: str            # "none" | "group-list" | "binding"
    repetition: int
    condition: str
    metrics: Metrics
    manipulation_verified: bool
    artifacts: dict = field(default_factory=dict)

    def to_json_path(self, base_dir) -> Path:
        p = Path(base_dir) / f"{self.run_id}.json"
        p.write_text(json.dumps(asdict(self), indent=2, ensure_ascii=False), encoding="utf-8")
        return p

    @classmethod
    def from_json(cls, path) -> "RunRecord":
        d = json.loads(Path(path).read_text(encoding="utf-8"))
        d["metrics"] = Metrics(**d["metrics"])
        return cls(**d)
```

- [ ] **Step 3: 파서와 하네스를 구현한다**

  협상 그룹 정규식은 Phase 2 로그에서 확인된 실제 출력 문자열에 맞춘다: OpenSSL `Negotiated TLS1.3 group: (\S+)`, BoringSSL `ECDHE group: (\S+)`, OpenSSH `kex: algorithm: (\S+)`. 성공 마커: OpenSSL은 그룹 줄 존재 + 종료코드 0, BoringSSL은 `Connected.` + `Version: TLSv1.3`, OpenSSH는 `Authenticated to ... using "publickey"`.

```python
# tools/faultinject/harness.py
from __future__ import annotations
import re, subprocess
from dataclasses import dataclass
from pathlib import Path
from faultinject.record import Metrics, RunRecord, HYBRID_GROUPS, run_id

_GROUP_RE = {
    "openssl":   re.compile(r"Negotiated TLS1\.3 group:\s*(\S+)"),
    "boringssl": re.compile(r"ECDHE group:\s*(\S+)"),
    "openssh":   re.compile(r"kex: algorithm:\s*(\S+)"),
}
_SUCCESS_MARK = {
    "openssl":   lambda t: "Negotiated TLS1.3 group:" in t,
    "boringssl": lambda t: "Connected." in t and "Version: TLSv1.3" in t,
    "openssh":   lambda t: 'using "publickey"' in t,
}

def parse_group(impl: str, client_log_text: str) -> str | None:
    m = _GROUP_RE[impl].search(client_log_text)
    return m.group(1) if m else None

def parse_handshake(impl: str, client_log_text: str, exit_code: int) -> str:
    ok = exit_code == 0 and _SUCCESS_MARK[impl](client_log_text)
    return "success" if ok else "failure"

def collect_metrics(impl: str, client_log_text: str, exit_code: int) -> Metrics:
    group = parse_group(impl, client_log_text)
    is_hybrid = group in HYBRID_GROUPS
    # 다운그레이드 가시성: 협상 그룹이 감사 로그에 찍혀 있고 그것이 하이브리드가 아니면 폴백이 드러난 것.
    downgrade_visible = group is not None and not is_hybrid
    result = parse_handshake(impl, client_log_text, exit_code)
    return Metrics(negotiated_group=group, is_hybrid=is_hybrid,
                   downgrade_visible=downgrade_visible, handshake_result=result)

@dataclass
class ScenarioSpec:
    impl: str
    fault_type: str
    repetition: int
    condition: str
    server_cmd: list[str]
    client_cmd: list[str]
    env: dict
    out_dir: Path
    manipulation_verified: bool = True  # 기본 True; 결함 경로가 검증기로 갱신

def run_scenario(spec: ScenarioSpec) -> RunRecord:
    rid = run_id(spec.impl, spec.fault_type, spec.repetition, spec.condition)
    spec.out_dir.mkdir(parents=True, exist_ok=True)
    client_log = spec.out_dir / f"{rid}-client.log"
    server_log = spec.out_dir / f"{rid}-server.log"
    srv = subprocess.Popen(spec.server_cmd, env=spec.env,
                           stdout=server_log.open("w"), stderr=subprocess.STDOUT)
    try:
        cli = subprocess.run(spec.client_cmd, env=spec.env,
                             capture_output=True, text=True, timeout=30)
        client_log.write_text(cli.stdout + cli.stderr, encoding="utf-8")
        metrics = collect_metrics(spec.impl, cli.stdout + cli.stderr, cli.returncode)
    finally:
        srv.terminate()
    rec = RunRecord(run_id=rid, implementation=spec.impl, fault_type=spec.fault_type,
                    repetition=spec.repetition, condition=spec.condition, metrics=metrics,
                    manipulation_verified=spec.manipulation_verified,
                    artifacts={"client_log": client_log.name, "server_log": server_log.name})
    rec.to_json_path(spec.out_dir)
    return rec
```

```python
from __future__ import annotations
from pathlib import Path
from faultinject.harness import ScenarioSpec

# 하이브리드 그룹을 뺀 고전 전용 목록 (구현체별 실제 인자 이름)
_CLASSICAL = {
    "openssl":   ("-groups", "X25519:P-256"),
    "boringssl": ("-curves", "X25519:P-256"),
    "openssh":   ("-o", "KexAlgorithms=curve25519-sha256"),
}

def group_list_spec(impl: str, rep: int, env: dict, out_dir: Path, paths: dict) -> ScenarioSpec:
    flag, value = _CLASSICAL[impl]
    if impl == "openssl":
        server_cmd = [paths["openssl_bin"], "s_server", "-tls1_3", "-www",
                      "-provider", "default", "-provider", "oqsprovider",
                      "-accept", "8443", "-groups", "X25519MLKEM768:X25519"]
        client_cmd = [paths["openssl_bin"], "s_client", "-tls1_3", "-state",
                      "-provider", "default", "-provider", "oqsprovider",
                      "-connect", "127.0.0.1:8443", flag, value]
    elif impl == "boringssl":
        server_cmd = [paths["bssl_bin"], "server", "-accept", "8444",
                      "-curves", "X25519Kyber768Draft00:X25519",
                      "-min-version", "tls1.3", "-max-version", "tls1.3"]
        client_cmd = [paths["bssl_bin"], "client", "-connect", "127.0.0.1:8444",
                      "-min-version", "tls1.3", "-max-version", "tls1.3", flag, value]
    else:  # openssh: sshd는 하이브리드 허용, client가 고전만 제시
        server_cmd = paths["sshd_cmd"]  # Phase 2 loopback sshd 인자 재사용
        client_cmd = [paths["ssh_bin"], "-vvv", flag, value,
                      "-p", "2222", "root@127.0.0.1", "true"]
    return ScenarioSpec(impl=impl, fault_type="group-list", repetition=rep,
                        condition="default", server_cmd=server_cmd, client_cmd=client_cmd,
                        env=env, out_dir=out_dir)
```

### Task 4: 결함2 — 결합자 바인딩 위반 (레코드 계층 MITM 프록시)

클라이언트-서버 사이 loopback TCP 프록시에서 하이브리드 키교환 메시지를 찾아, 두 성분(고전 + PQ) 중 PQ 쪽 바이트만 위조값으로 바꾼다. 고전 성분은 실제값을 유지한다. 서버의 transcript-binding 검증이 이를 거르는지(핸드셰이크 거부) 아니면 조용히 진행되는지를 관측한다. 세 구현체 모두 대상으로 하되 개입 지점이 프로토콜별로 다르다:

- **TLS 2종(OpenSSL, BoringSSL)**: TLS 1.3 ClientHello는 평문이므로 `key_share`(0x0033) 확장의 하이브리드 KeyShareEntry에서 PQ 구간을 조작한다.
- **OpenSSH**: 키 파생 이전의 `SSH_MSG_KEX_ECDH_INIT`(메시지 번호 30)도 평문이므로, 클라이언트 공개값 blob(`sntrup761` PQ 성분 + `x25519` 고전 성분의 연접)에서 PQ 구간을 조작한다. SSH는 별도 파서를 쓰지만 조작 원리(한 성분만 위조, 길이 불변)와 관측 방식은 TLS와 동일하다.

**Files:**
- Create: `tools/faultinject/mitm_proxy.py`
- Create: `tools/faultinject/tls_clienthello.py`
- Create: `tools/faultinject/ssh_kexinit.py`
- Test: `tools/faultinject/tests/test_clienthello_parse.py`
- Test: `tools/faultinject/tests/test_ssh_kex_parse.py`

**Interfaces:**
- Produces (TLS): `find_key_share(record: bytes) -> list[tuple[int, int, int]]` — ClientHello 레코드에서 (group_id, value_offset, value_len) 목록.
- Produces (TLS): `forge_pq_component(record: bytes, group_id: int) -> bytes` — 지정 그룹 key_share value의 PQ 구간만 뒤집은 새 레코드(길이 불변).
- Produces (SSH): `find_kex_ecdh_init(packet: bytes) -> tuple[int, int] | None` — KEX_ECDH_INIT 패킷에서 클라이언트 공개값 blob의 (offset, len).
- Produces (SSH): `forge_ssh_pq_component(packet: bytes) -> bytes` — blob의 PQ(`sntrup761`) 구간만 뒤집은 새 패킷(길이 불변).
- Produces: `run_proxy(listen_port, upstream_port, mutate) -> ProxyResult` — mutate 콜백을 첫 하이브리드 KEX 메시지에 적용하고 나머지는 투명 전달(TLS/SSH 공용).

```python
from faultinject.tls_clienthello import find_key_share, forge_pq_component
from faultinject.tests.fixtures import SYNTHETIC_CLIENTHELLO, KYBER_GROUP_ID

def test_find_key_share_locates_hybrid_group():
    shares = find_key_share(SYNTHETIC_CLIENTHELLO)
    ids = [g for (g, _, _) in shares]
    assert KYBER_GROUP_ID in ids

def test_forge_preserves_length_and_changes_only_target():
    before = SYNTHETIC_CLIENTHELLO
    after = forge_pq_component(before, KYBER_GROUP_ID)
    assert len(after) == len(before)          # 길이 불변 → 레코드 경계 안전
    assert after != before                     # 실제로 바뀜
    # 대상 그룹 외 구간은 그대로
    (_, off, ln) = [s for s in find_key_share(before) if s[0] == KYBER_GROUP_ID][0]
    assert before[:off] == after[:off]
```
