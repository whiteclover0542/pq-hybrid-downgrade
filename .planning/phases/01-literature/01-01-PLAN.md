# Phase 1 Literature Research Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 검증 가능한 선행연구와 CVE 원문 근거를 수집해 하이브리드 PQ 다운그레이드 연구의 알려진 사실, 새 주장, 기준 사례를 분리한다.

**Architecture:** 문헌·CVE별 증거를 하나의 source ledger에서 추적하고, CVE-2026-2673과 배경 CVE는 별도 분석 노트로 분리한다. 마지막에 검증된 근거만 사용해 가설과 연구 질문을 고정하는 synthesis 노트를 만든다.

**Tech Stack:** Markdown, 공식 보안 권고문·NVD·학술 출판물, 브라우저 기반 원문 확인, 로컬 체크리스트 검증.

**Spec:** `.planning/REQUIREMENTS.md`의 `REQ-prior-work-verification`, `.planning/ROADMAP.md`의 Phase 1 성공 기준.

## Global Constraints

- AI가 제안한 문헌은 원문에서 제목·저자·연도·초록을 직접 확인하기 전까지 근거로 사용하지 않는다.
- CVE-2026-2673은 권고문, 영향 버전, 결함 메커니즘을 원문 근거와 함께 기록한다.
- FreeRDP, Cisco, NGINX 배경 CVE는 NVD 항목과 원출처를 대조한다.
- 검증 실패·불일치 문헌은 참고문헌에 포함하지 않고 제외 사유를 기록한다.
- 연구의 새 주장과 이미 알려진 사실을 별도 항목으로 유지한다.
- 원문 확인 URL, 확인 날짜, 확인 방법을 각 증거 항목에 남긴다.

## Review Focus

- 제목은 존재하지만 실제 논문 내용이 하이브리드 컴바이너와 무관한 경우 — 서지정보와 초록을 모두 대조한다.
- 저자·연도·제목이 서로 다른 논문을 하나의 인용으로 합치는 경우 — DOI, 출판 페이지 또는 공식 프리프린트 식별자를 기록한다.
- CVE 번호와 영향 제품·버전이 혼합되는 경우 — NVD와 벤더 권고문을 각각 대조한다.
- CVE 설명의 영향 문장을 결함 메커니즘으로 과해석하는 경우 — 권고문에 직접 적힌 사실과 연구자의 해석을 분리한다.
- 출처가 삭제되거나 접근 불가한 경우 — 확인 실패를 결과로 기록하고 근거 목록에서 제외한다.

- [x] **Step 1: 조사 대상과 증거 필드를 고정한다**

  `phase-1-source-ledger.md`에 다음 출처 ID를 만든다: `LIT-01`(Bhargavan et al. 정의), `LIT-02`(Transcript-Bound Combiners 논문), `CVE-01`(CVE-2026-2673), `CVE-02`(FreeRDP CVE-2026-91949), `CVE-03`(Cisco CVE-2026-20249), `CVE-04`(NGINX CVE-2026-90439). 각 행의 필드는 `주장`, `후보 출처`, `원문 URL/식별자`, `확인 날짜`, `검증 상태`, `원문 근거 요약`, `가설 연결`, `제외 사유`로 고정한다.

- [x] **Step 2: 알려진 사실과 새 주장을 구분하는 표를 만든다**

  `phase-1-synthesis.md`에 `이미 알려진 사실`, `이번 연구에서 검증할 새 주장`, `주장별 필요한 증거`, `판정 상태` 열을 만든다. 아직 검증하지 않은 항목은 `검증 전`으로 표시하고 사실처럼 서술하지 않는다.

- [x] **Step 3: 문서 구조를 확인한다**

  실행: `Get-Content -Raw -Encoding utf8 docs/research/phase-1-source-ledger.md` 및 `Get-Content -Raw -Encoding utf8 docs/research/phase-1-synthesis.md`

  기대 결과: 6개 조사 대상 ID와 알려진 사실/새 주장 구분 표가 존재한다.

### Task 2: 하이브리드 컴바이너 선행연구 검증

**Files:**
- Modify: `docs/research/phase-1-source-ledger.md`
- Modify: `docs/research/phase-1-synthesis.md`

**Interfaces:**
- Consumes: `LIT-01`, `LIT-02` 행과 공식 출판 페이지·프리프린트·저자 페이지의 원문
- Produces: 검증된 서지정보, 초록 기반 내용 요약, 가설 연결, 검증 실패·제외 기록

- [x] **Step 1: Bhargavan et al. 출처를 확인한다**

  제목·저자·발행 연도·출판 식별자를 원문에서 확인하고, 다운그레이드 저항성 정의가 적힌 위치를 기록한다. 검색 결과 페이지만 확인된 경우에는 검증 상태를 완료로 바꾸지 않는다.

- [x] **Step 2: Transcript-Bound Combiners 논문을 확인한다**

  제목·저자·연도·초록과 하이브리드 키 설정 및 transcript binding에 관한 주장을 원문에서 확인한다. 논문이 존재하지 않거나 제목과 내용이 불일치하면 `LIT-02`를 제외 상태로 남기고 사유를 적는다.

- [x] **Step 3: 각 문헌을 가설에 연결한다**

  각 검증 문헌에 대해 “설계 수준의 다운그레이드 저항성”, “transcript-bound 결합”, “실제 구현의 as-deployed 안전성 검증” 중 어떤 부분을 뒷받침하는지 한 문장으로 기록한다.

- [x] **Step 4: 인용 검증 결과를 점검한다**

  확인되지 않은 문헌이 synthesis의 근거 문장에 남아 있지 않은지 검색한다. 실행: `rg -n "검증 전|검증 실패|제외|LIT-01|LIT-02" docs/research`

  기대 결과: 각 `LIT-*` 행에 검증 상태와 출처 식별자가 있고, 제외된 문헌에는 사유가 있다.

### Task 3: CVE-2026-2673 소스 수준 분석

**Files:**
- Create: `docs/research/cve-2026-2673.md`
- Modify: `docs/research/phase-1-source-ledger.md`

**Interfaces:**
- Consumes: `CVE-01` 후보 행, OpenSSL 공식 security advisory, NVD, 관련 수정 커밋 또는 공식 설명
- Produces: 영향 버전, 공격 전제조건, 결함 메커니즘, 영향, 수정 정보가 출처별로 분리된 분석 노트

- [x] **Step 1: CVE 원문 식별정보를 기록한다**

  `cve-2026-2673.md`에 CVE 번호, 공개일, OpenSSL 권고문 URL, NVD URL, 확인 날짜를 기록하고 권고문과 NVD가 같은 제품·버전을 가리키는지 대조한다.

- [x] **Step 2: 영향 범위를 고정한다**

  영향 OpenSSL 계열과 버전 범위를 권고문 원문에서 옮겨 적고, oqs-provider 또는 하이브리드 그룹과의 관계가 원문 사실인지 연구 맥락의 연결인지 구분한다.

- [x] **Step 3: 결함 메커니즘을 사실과 해석으로 나눈다**

  분석 노트에 `권고문이 직접 말하는 사실`, `소스/수정 내용으로 확인한 메커니즘`, `이번 연구에서 시험할 해석` 세 구역을 만들고 각각의 출처를 붙인다.

- [x] **Step 4: Phase 1 기준 사례를 확정한다**

  source ledger의 `CVE-01`에 검증 상태, 영향 버전, 결함 메커니즘 요약, 연구 가설과의 연결을 반영한다. 원문이 주장을 지지하지 않으면 기준 사례 설명을 수정하고 수정 이유를 남긴다.

### Task 4: 배경 CVE 3건 재확인

**Files:**
- Create: `docs/research/background-cves.md`
- Modify: `docs/research/phase-1-source-ledger.md`

**Interfaces:**
- Consumes: `CVE-02`~`CVE-04`, 각 NVD 항목과 가능한 경우 벤더 권고문
- Produces: 세 CVE의 존재·제품·취약점 위치·겉보기 정상 동작 관련 근거와 불일치 기록

- [x] **Step 1: FreeRDP CVE-2026-91949를 확인한다**

  NVD의 설명, 영향 제품·버전, 참조 링크를 기록하고 FreeRDP 항목이 프로젝트의 “협상/핸드셰이크 단계 결함” 맥락과 실제로 연결되는지 별도로 판정한다.

- [x] **Step 2: Cisco CVE-2026-20249를 확인한다**

  NVD와 Cisco 보안 권고문을 대조해 제품, 공격 조건, 취약점 위치를 기록한다. 프로젝트 배경과 일치하지 않는 부분은 억지로 일반화하지 않고 차이점으로 적는다.

- [x] **Step 3: NGINX CVE-2026-90439를 확인한다**

  NVD와 NGINX/OpenSSL 관련 공식 참조를 대조해 제품·버전·프로토콜 범위를 기록한다. OpenSSL 버전 조건이 별도라면 해당 조건을 명시한다.

- [x] **Step 4: 세 항목을 비교한다**

  `background-cves.md`에 CVE, 제품, 결함 위치, 관찰 가능한 정상성, 프로젝트와의 관련성, 출처를 표로 정리하고 관련성이 낮거나 불일치하는 항목은 제외 사유를 적는다.
