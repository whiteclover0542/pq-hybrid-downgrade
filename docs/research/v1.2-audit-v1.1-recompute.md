# v1.1 90건 감사 가시성 재계산

## 0. 재계산 도구 버전

[확실] 재계산에 사용한 도구는 `tools/faultinject/audit.py`이며, 커밋 `f99f79b1b36feac06069035c3e1dc44dd55a98d5`("feat(v1.2): measure audit visibility per output path (audit.py)")의 상태에서 실행했다. 이 값은 WSL(Ubuntu, tshark 4.6.4 설치됨)에서 아래 명령이 출력한 `git rev-parse HEAD` 그대로다.

```
wsl -d Ubuntu -u root -- bash -lc 'cd /mnt/d/IT/git/PERSONAL/pq-hybrid-downgrade/pq-hybrid-downgrade/tools && git rev-parse HEAD && python3 -m faultinject.audit --v11 --out ../docs/research/v1.2-audit-v1.1-recompute.json'
```

[확실] 아래 표의 각 셀 값(`explicit_warning`, `mismatch_in_single_output`)의 근거는 사람이 다시 읽을 수 있는 원문 조각으로 `docs/research/v1.2-audit-v1.1-recompute.json`의 `[].audit.paths.<경로>.evidence`에 그대로 보존되어 있다(설계 §7 "재계산 도구의 버전과 값의 근거 경로를 별도 보고"). v1.1의 원시 `docs/research/baselines/raw/v1.1/` 파일은 이 재계산 동안 읽기만 했고 수정하지 않았다(`git status --short docs/research/baselines/raw/v1.1` 출력 없음으로 확인).

## 1. v1.1 `downgrade_flagged`는 측정값이 아니었다

[확실] v1.1 레코드의 `metrics.downgrade_flagged`는 `tools/faultinject/harness.py`의 `audit_flags_downgrade()`가 만든 값인데, 이 함수는 입력(`advertised_hybrid`, `negotiated_is_hybrid`)과 무관하게 항상 `False`를 반환하도록 구현되어 있다(코드 주석: "standard audit tools do NOT auto-surface an advertised-hybrid-vs-negotiated-classical mismatch ... So this always returns False (= silent), regardless of inputs."). 즉 이 필드는 "표준 감사 도구가 불일치를 자동으로 드러내지 않는다"는 설계상 상수이지, 실제 출력을 읽고 판정한 실측값이 아니다. 본 과제는 이를 `audit.py`의 경로별 실측(`explicit_warning`, `mismatch_in_single_output`)으로 대체한다.

## 3. 경로별 해석 규칙

[확실] `audit.py`가 적용하는 판정 정의(설계 §6.2)는 다음과 같다.

- `explicit_warning`: 해당 경로의 출력이 존재하고, 경고 서명(`downgrad*`, `insecure`, `security warning`, `policy` 중 하나, 대소문자 무관)이 **없을 때만** `False`. 출력 자체가 없으면(`None`) 미확인이다. 서명이 있으면 `True`이고 원문이 `evidence.warning`에 남는다.
- `mismatch_in_single_output`: 한 출력 안에서 **광고한 하이브리드 그룹 이름**(`supported_groups`/`KEX algorithms` 줄에 `X25519MLKEM768`/`X25519Kyber768Draft00`/`sntrup761x25519` 중 하나)과 **협상 결과 줄**(`Negotiated TLS1.3 group:`/`ECDHE group:`/`Peer Temp Key:`/`kex: algorithm:`)이 **모두** 보일 때만 `True`. 출력은 있는데 둘 중 하나만 있으면 `"unsupported"`. 출력이 없으면 `None`.
- 경로 통합(`summarize_paths`): 여러 경로 중 하나라도 `True`면 레코드 전체가 `True`, 아니면 하나라도 `False`가 있으면 `False`, 그 외에는 `None`(미확인)이다. `basis`는 `True` 판정에 기여한 경로 이름 목록이다.

[확실] 실제 관측 사례로, `openssh_condition_r01_base`의 `client_log` 경로는 `advertised = "KEX algorithms: sntrup761x25519"`, `negotiated = "kex: algorithm: sntrup761x25519-sha512@openssh.com"`을 한 로그 안에서 동시에 포착해 `mismatch_in_single_output = True`가 되었다(`basis: ["client_log"]`). 반면 OpenSSL/BoringSSL의 `-msg` 로그는 협상 결과 줄(`ECDHE group:`/`Negotiated TLS1.3 group:`)만 있고 광고한 그룹 이름 줄(`supported_groups`)은 찍히지 않으므로 `"unsupported"`로 남는다 — 이는 "결과는 보이지만 광고 대비 비교는 단일 출력만으로 안 된다"는 실제 도구 한계를 그대로 반영한 것이다.

## 4. `explicit_warning=True` 사례 검토

[확실] 90건 전부에서 `explicit_warning`은 `False`였고 `True`인 경로/레코드는 0건이다(JSON을 `explicit_warning is True`로 필터링해 직접 확인). 따라서 인용하거나 오탐 여부를 판정할 `evidence.warning` 원문이 존재하지 않는다. `WARNING_RE`가 `policy`처럼 일반적인 단어도 매칭하도록 넓게 잡혀 있어 오탐 위험이 있음을 설계 시점부터 인지하고 있었으나, v1.1의 client/server 로그와 tshark 요약에는 해당 단어들이 전혀 등장하지 않아 이번 90건에서는 오탐 검토 대상 자체가 없었다.

## 5. 수집하지 않은 경로

[확실] `s_client -brief`와 `keylog` 두 경로는 v1.1 실행에서 수집하지 않았으며, `audit_record`는 이를 `mismatch_in_single_output = "not_collected"`, `explicit_warning = None`으로 고정하고 사유를 `evidence`에 남긴다.

- `s_client -brief`: v1.1 클라이언트는 `-state -msg` 옵션으로 실행되어 `-brief` 출력 자체를 캡처하지 않았다.
- `keylog`: NSS 키 로그 파일을 남기지 않았다. 설사 있었더라도 키 로그 줄은 레이블·client random·비밀값만 담고 있어 그룹 이름을 담지 않으므로, 애초에 이 지표의 근거로 쓸 수 없는 자료다.

[확실] 이 두 경로의 부재는 Task 10 논문 한계 절에 별도로 명시한다(본 문서 범위 밖).
