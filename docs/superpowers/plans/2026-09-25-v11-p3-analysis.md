# v1.1 P3 Analysis Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Produce a reproducible P3 analysis of the validated v1.1 P2 dataset without updating the paper.

**Architecture:** Read the 90 final JSON records from `raw/v1.1/` as the sole source of numerical claims. Compare their counts with the P2 execution summary and interpret them using the pre-registered v1.1 design's definitions of silent-downgrade, transcript protection, and audit visibility. Keep the OpenSSH result as a structural control, not an equivalence claim.

**Tech Stack:** Python 3 JSON parsing, PowerShell read-only file checks, Markdown research documentation.

**Spec:** `docs/research/2026-09-23-v1.1-hrr-downgrade-design.md`; `.planning/phases/07-v11-tooling/07-02-SUMMARY.md`.

## Global Constraints

- Do not change `docs/PAPER.md`, `docs/PROPOSAL.md`, or the reproduction package; those are P4 deliverables.
- Cite raw `docs/research/baselines/raw/v1.1/*.json` records for every numerical P3 claim.
- State that P2 establishes observations under this testbed and manipulation definition; do not claim a new vulnerability beyond the evidence.
- Preserve the distinction between `downgrade_flagged=False` and absence of a manual audit conclusion.
- Treat the OpenSSH on-path result as a failed connection with a parsed hybrid group, not a negotiated downgrade.

## Review Focus

- Silent-downgrade numerical claims must distinguish advertised hybrid support, classical negotiated group, success, HRR absence, and audit flag.
- On-path TLS results must be described as transcript-protection observations, not as proof of a universal protocol property.
- OpenSSH on-path-strip must remain a failure observation even though `is_hybrid=True` is recorded.
- RFC conformance must be framed as a possibility that requires normative analysis, not as an established conclusion from P2.
- Every analysis table total must sum to 10 per valid implementation/condition combination and 90 overall.
