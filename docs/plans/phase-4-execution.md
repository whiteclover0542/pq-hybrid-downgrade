# Phase 4 — 실험 실행

상태: ⬜ 미완료

## 목표

실험 설계를 확정하고, 정한 대로 끝까지 반복 실행해 원자료를 남긴다. 결과를 유리하게 고르지 않도록 조건과 반복 횟수를 실행 전에 고정한다.

## 실험 설계 (실행 전 확정)

| 항목 | 내용 |
| --- | --- |
| 바꾸는 조건 | 구현체(3종) × 결함 유형(그룹 목록 조작 / 컴바이너 바인딩 위반) |
| 고정하는 조건 | 하이브리드 그룹 설정, 네트워크 환경, 감사·로깅 설정 |
| 반복 횟수 | 조합당 최소 10회 |
| 측정값 | ① 협상 결과 그룹(하이브리드/고전) ② 감사 도구 탐지 여부 ③ 핸드셰이크 성공/실패 |

## 할 일

- [ ] 시험 삼아 1회 실행 — 기록 방식에 빠진 값 없는지 확인
- [ ] 정한 조합대로 반복 실행 (구현체 × 결함 유형 × 10회 이상)
- [ ] 매 실행 로그·패킷 캡처를 파일로 저장 (실행 조건이 파일명/메타에 드러나게)
- [ ] 설계를 도중에 바꿨다면 언제·무엇을·왜 바꿨는지 기록 (이전 데이터는 지우지 않음)

## 산출물

- 원자료 파일 (로그, 패킷 캡처) — 건수가 설계 표본 수와 일치
- 실행 스크립트 또는 절차 설명

## 완료 기준

- 원자료 건수가 설계에 적힌 표본 수와 어긋나지 않는다.
- 다른 사람이 절차를 따라 결과를 다시 확인할 수 있다.

## 주의

- 결과가 매번 다르면 그 흔들림 자체를 기록한다 — 그것도 발견이다.
- 가설이 기각되는 결과도 그대로 남긴다. 맞추려 고치지 않는다.
