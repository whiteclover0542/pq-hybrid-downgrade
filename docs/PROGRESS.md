### Phase 1 — 문헌 조사

- [ ] 하이브리드 컴바이너 다운그레이드 저항성 관련 선행 연구 목록화
  - [ ] Bhargavan et al.의 다운그레이드 저항성 정의 확인
  - [ ] “Transcript-Bound Combiners for Downgrade-Resilient Hybrid PQ Key Establishment” 확인
- [ ] 각 문헌의 제목·저자·연도·초록을 원문에서 확인
- [ ] 각 문헌이 가설의 어느 부분을 뒷받침하는지 한 줄로 기록
- [ ] 실존하지 않거나 내용이 다른 문헌은 제외 사유 기록
- [ ] CVE-2026-2673 OpenSSL security advisory 원문 확인
  - [ ] 영향 버전 확인
  - [ ] 결함 메커니즘 정리
- [ ] 배경 CVE 3건(FreeRDP·Cisco·NGINX)의 NVD 항목 재확인

### Phase 2 — 실험 환경 구축

- [ ] OpenSSL + oqs-provider 빌드
  - [ ] CVE-2026-2673 대상 버전/커밋 고정
  - [ ] 하이브리드 그룹으로 `s_server`/`s_client` 핸드셰이크 성공 확인
- [ ] BoringSSL 빌드
  - [ ] 하이브리드 그룹으로 핸드셰이크 성공 확인
- [ ] OpenSSH 하이브리드 KEM 빌드 및 설정
  - [ ] `sntrup761x25519-sha512` 등 대상 알고리즘으로 SSH 핸드셰이크 성공 확인
- [ ] 구현체별 버전·커밋 해시·빌드 옵션 기록
- [ ] SSLKEYLOGFILE, `s_server -state`, `sshd -vvv` 등 감사·로깅 경로 확인
- [ ] 정상 하이브리드 핸드셰이크 baseline 로그와 패킷 캡처 저장

### Phase 3 — 실험 도구 개발

- [ ] 클라이언트·서버 사이 Fault Injector 골격 구현
  - [ ] TLS 레코드 계층 가로채기 경로 구현
  - [ ] 필요한 경우 mitmproxy류 확장 또는 저수준 후킹 검토
- [ ] 결함 유형 1 구현 — 그룹 목록 조작
  - [ ] `supported_groups`/KEX 목록에서 하이브리드 그룹 제거
  - [ ] `supported_groups`/KEX 목록 순서 변경
- [ ] 결함 유형 2 구현 — 컴바이너 바인딩 위반
  - [ ] 고전 성분만 실제 값으로 유지하는 경우 구현
  - [ ] PQ 성분만 실제 값으로 유지하는 경우 구현
  - [ ] 나머지 성분을 조작 값으로 바꾸는 경우 구현
- [ ] 결과 수집 하네스 구현
  - [ ] 협상 결과 그룹 기록
  - [ ] 감사 도구 탐지 여부 기록
  - [ ] 핸드셰이크 성공/실패 기록
- [ ] 조작 반영 여부를 확인하는 짧은 검증 스크립트 작성
- [ ] 도구 동작 확인 후 3개 구현체에 적용 가능 여부 확인

### Phase 4 — 실험 실행

- [ ] 실험 조건을 실행 전에 고정
  - [ ] 구현체 3종 × 결함 유형 2종 조합 확정
  - [ ] 하이브리드 그룹·네트워크·로깅 설정 고정
  - [ ] 조합당 최소 10회 반복 횟수 확정
- [ ] 시험 실행 1회로 기록 누락 여부 확인
- [ ] 각 조합을 정해진 반복 횟수 이상 실행
- [ ] 매 실행의 로그·패킷 캡처 저장
  - [ ] 파일명에 구현체·결함 유형·반복 번호 포함
  - [ ] 실행 조건과 메타데이터 함께 저장
- [ ] 설계 변경 시 변경 시점·내용·이유 기록
- [ ] 이전 원자료를 삭제하지 않고 변경 전후 데이터 보존

### Phase 5 — 결과 분석

- [ ] 예상과 다른 결과의 원인 후보 검토
